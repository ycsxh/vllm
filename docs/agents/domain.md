# Domain Docs

This repository uses a single-context domain-document layout.

## Before exploring

Read `CONTEXT.md` at the repository root when it exists, followed by relevant
ADRs under `docs/adr/`.

If these files do not exist, proceed silently. Domain-modeling workflows create
them lazily when terminology or architectural decisions need to be recorded.

## Vocabulary

Use terminology defined in `CONTEXT.md` consistently in specifications, issue
titles, tests, and implementation. Surface conflicts with existing ADRs rather
than silently overriding them.

## Layout

- `CONTEXT.md`: repository-wide glossary and domain context
- `docs/adr/`: repository-wide architectural decisions
